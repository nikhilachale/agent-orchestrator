The agent is the piece that actually writes code. Everything else in AO — worktrees, runtimes, notifiers — is plumbing around it.

<Callout type="info">
	**PR metadata is captured automatically.** Several non-Claude-Code agents (including Codex, Cursor, Aider, and
	OpenCode) use `~/.ao/bin/gh` and `~/.ao/bin/git` PATH wrappers that intercept commands like `gh pr create` and record
	the resulting PR number and branch so the dashboard stays in sync. Claude Code uses PostToolUse hooks in
	`.claude/settings.json` instead — the same metadata is written through Claude Code's native hook system. Both
	approaches are set up transparently by AO; you don't need to configure anything.
</Callout>

## Choosing

- **Want session resume** (pick up where you left off)? Claude Code, Codex, or OpenCode.
- **Fresh launch per AO restore** is fine? Prime Agent and other non-resumable harnesses are supported.
- **Pair-programming style editor**? Aider.
- **Native IDE-like behavior in the terminal**? Cursor.

## How AO talks to them

Prime Agent uses an AO-managed TypeScript extension under `AO_DATA_DIR` for lifecycle activity. Other adapters use their
native event surfaces, AO-managed integrations, or terminal/runtime signals according to what the harness safely exposes.

You do not need to edit Prime Agent's extension configuration; AO installs and passes its managed extension automatically.

## Mixing agents

Per-project overrides:

```yaml
defaults:
  worker:
    agent: claude-code
projects:
  api:
    repo: myorg/api
    worker:
      agent: codex
  web:
    repo: myorg/web
    worker:
      agent: cursor
```

You can also override at spawn time:

```bash
ao spawn --project api --agent codex --name worker
```

Great for A/B testing which agent does better on a specific kind of issue.
